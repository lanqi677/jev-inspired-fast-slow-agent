# 总览 · 这个目录里是什么、先看哪个

> 一句话：**从"研究 Jev 快决策"开始，最后落成了一个「描述 + 适配器」驱动的通用执行引擎** ——
> 同一份引擎，挂 `sitea.json` 跑真实内网后台，挂 `snake.json` 玩网页贪吃蛇，**引擎里没有一行领域专有代码**。

---

## 一、先看这个：结论已经收敛

| # | 问题 | 结论 |
|---|---|---|
| 1 | 本机能本地跑 Jev 类模型吗？ | **不能。** 兆芯 KX-7000 无 GPU，纯 CPU 下 Jev 式决策要 1.9–11.9 秒，比 Jev 宣称的 70–500ms 慢 **8–70 倍** |
| 2 | Jev 到底新在哪？ | **技术创新很少**（两小时可复现），是**需求侧创新**：把古老的"分类器"包装成通用 API、按输入计费、把"校准置信度"写进契约 |
| 3 | 用云 API 做快决策行吗？ | **行。** schema 18/18 合规、60 选项全覆盖、多题隔离成立、置信度随证据变化。**单步 ≈ $0.0001 / 151ms** |
| 4 | 延迟够快吗？ | **看窗口。** 快窗口 210–400ms，慢窗口 600–1200ms，跨度约 5 倍。**不能按 250ms 内环设计** |
| 5 | 能做 computer use 吗？ | **能，但收窄到浏览器。** 桌面路线要截图 1024 token/次 + 坐标 + 多平台辅助功能栈，全被浏览器路线消掉 |
| 6 | **最后做出了什么？** | **一个三层引擎**：①通用引擎 ②站点/环境适配器（数据） ③任务描述。**引擎零领域代码**，换环境只换适配器 |
| 7 | 泛化性验证了吗？ | **验了。** 同一引擎跑通真实内网后台 + 网页贪吃蛇。适配器由**推理模型产出**（一个网页一次），但还没固化成"一条命令"的可重复流程 |

## 二、现在手上有什么

### A. 能直接用的（这才是成果）

| 文件 | 是什么 |
|---|---|
| **`general/engine.mjs`** | **引擎本体**（≈790 行）。感知/决策/执行/事实/判定/护栏/反思都在里面，**跨任务跨领域不变** |
| **`general/adapter.mjs`** | **适配器层**。把任意环境翻译成统一表示 `{stateText, options}`。四件套：状态编码/可选项/动作执行/终止判定 |
| **`general/adapters/*.json`** | 适配器实例。`sitea.json`（dom 型，纯选择器+正则）、`siteb.json`、`snake.json`（custom 型，带一小段代码） |
| **`general/browser.mjs`** | **常驻浏览器**：看得见、登录态长期保留。`start/status/goto/dump/min/restore/max/stop` |
| `general/task_*.txt` | 任务描述（自然语言）。**改任务只改这个** |
| `general/games/snake.html` | 贪吃蛇测试台。步进驱动、食物随机、可传 `?seed=` 复现 |
| `general/mocks.json` | 真实地址 → 本地 mock 页的映射表（**所以引擎里没有 SiteA/SiteB 字眼**） |
| `general/verify_adapter.mjs` | 量化验证：同一页面跑两遍（无适配器 vs 有适配器），直接看出适配器有没有被消费 |
| `ops_scenario/mock_*.html` | 两个内网页的等价 mock（6 种分支数据），**不联内网就能跑** |

**跑法**：
```bash
cd general

# 真实内网（先 node browser.mjs start <url> 手工登录一次，之后长期有效）
ATTACH=1 CDP_PORT=9240 ADAPTER=sitea TASK_FILE="task_sitea工号存在性.txt" node engine.mjs

# 贪吃蛇（自动进 loop 模式）
ATTACH=1 CDP_PORT=9240 ADAPTER=snake TASK_FILE="task_贪吃蛇.txt" node engine.mjs

# mock 六分支（自带浏览器，不碰常驻那个）
OPS_MOCK=1 OPS_V=dup_email OPS_DV=ok TASK_FILE="task_账号排查.txt" node engine.mjs
```

## 三、已经确定成立、不用再验的结论

1. 本机（KX-7000，无 GPU）跑不了 Jev 类模型 —— **CPU 集群还有坑**：2×4 核，8 线程反而崩（13.44 → 5.47 tok/s），必须 `taskset -c 0-3 -t 4`
2. Jev 的技术内核是现成的；**"输出免费"是它唯一的结构性价格优势**
3. **置信度是"分流校验强度"的信号，不是"允许/禁止执行"的开关**
4. **护栏必须由代码做** —— 实测模型会照指令去点「删除」
5. **台账/进度/成功判定归代码** —— 让快模型记计划进度，它会反复重复第一步
6. **事实有时间语义** —— 必须在指定动作之后定点采集并冻结
7. **元素类型必须由代码把关** —— 否则模型会把「搜索框」选成「搜索按钮」，引擎照做还返回成功
8. **比较符/动作词表必须静态体检** —— 出现词表外的符号，规则会**恒为假**，而且完全无声
9. 浏览器路线消掉了：截图 token、坐标/DPI、多平台辅助功能栈、抢鼠标；**最小化后自动化照跑**
10. **视觉**：编号框方案在 `original` 下可用；`detail:"low"` 禁用；2560×1600 全屏时 12px 标签会被缩糊
11. **"改描述就能换策略"成立，但只到规则层**：贪吃蛇两批种子 A/B（n=20）实测，只改描述把平均分从 **6.30 抬到 9.25**、达标率 **50%→75%**，**代码零改动**；
    但**消除不了「撞自己」** —— 把规则逐字写成代码的完美执行者也 **8/8 死于把自己围死**。详见 `general/贪吃蛇策略改进验证.md`
12. **整局是确定性的**：同一随机种子在 Linux（UOS + KX-7000）与 Windows（Chrome 153）上得分**逐位一致**（10 / 9 / 4）

## 四、还没解决的

### 🔴 第一号缺口：**规划器不稳定，且失败是间歇的**

- 同一个任务两次拆解**不一样**（事实编号每次都变，规则条数会变）
- 在最终代码上混合连跑 **25 次 → 23 过 / 2 败（92%）**；但失败的 `dup_email` **单独跑 16/16 全过**
- **根因未定位**——针对性复现 10 次没抓住
- `checkPlan` 只能拦**结构性**缺陷（词表外操作符、没人采集的事实、类型不符），拦不住**语义性**错误

### 🟠 第二号缺口：**适配器生成还没固化成可重复流程**

> **适配器是推理模型写的（一个网页一次），但还是一条条现写，没有固化成一条命令。**

闭环本身是通的 —— 模型侦察页面、产出适配器，这已经在发生。
缺的是**产品化那一层**：一条命令完成「侦察 → 产出 `adapters/*.json` → 自检」，
以及"换一个全新的、没见过的网页，能不能稳定一次写对"的回归数据。
现在格式、消费者、验证手段都齐了，所以这件事终于**可以**做了。

### 🟡 其它

| 缺口 | 说明 |
|---|---|
| **两种模式没统一** | `plan`（先规划再执行）和 `loop`（每步现决定）是两条代码路径；loop 还**不能向输入框填值** |
| **没有结构化运行日志** | 失败时无法 diff"这次的计划 vs 上次的计划"，所以间歇失败查不动 |
| **`verify()` 是死代码** | 结论复核函数写了但**从没被调用**——现在所有结论都没有第二道校验 |
| **常驻浏览器偶发卡死** | 已加自愈（自动拉起），但根因没找到 |
| **只验了 1 个分支于真实站点** | 真实 SiteA 只跑通"工号存在"这一支，其余 5 支在 mock 上 |
